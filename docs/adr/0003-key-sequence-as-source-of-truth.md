# 以按鍵序列為唯一事實來源，引擎不丟棄按鍵

一般注音輸入法（例如新酷音）在編輯區裡存的是已經拼好的注音，拼不出合法讀音的按鍵會直接消失。mofoim 的容錯需要在事後依前後文重新解讀按鍵，所以我們決定引擎原封不動保留按鍵序列，編輯區的內容每次都從按鍵序列重新猜出來；「哪幾個鍵算一個字」不事先切死，而是由引擎同時嘗試多種切法，交給語言模型決定。

不事先切字的原因是：即使只處理誤觸，聲調鍵也可能被按成相鄰的符號鍵（大千的 `4` 旁邊是 `e` 與 `r`），字的邊界本來就不確定。

## Consequences

- 第一版只實作誤觸（按到相鄰鍵，按鍵數量不變）。漏按、多按、聲調鍵順序顛倒與自動判斷英文，之後都是「對同一串按鍵多加一種解讀方式」，不需要改資料結構。
- 同一個字裡，聲調鍵之前的聲母、介音、韻母不管按的順序，也不扣分。兩手幾乎同時按下時順序常常顛倒，一般的注音輸入法也不在乎這個順序，所以這不算打錯。聲調鍵仍然必須是最後一個鍵，否則字在哪裡結束會變得不確定。
- 引擎第一版沒有游標的概念：倒退鍵只刪除按鍵序列的最後一個按鍵，手動選字以「第幾個字」指定位置，由前端決定使用者如何指定。（這一點已由 [ADR 0004](0004-movable-cursor-and-pinned-segments.md) 取代。）
- 因為保留了原始按鍵，可以提供原樣送出。
- 容錯不能讓原本打對的句子變差：準確率測試同時量測「完全打對」與「加入誤觸」兩種情況，前者不得因容錯而明顯下降。
