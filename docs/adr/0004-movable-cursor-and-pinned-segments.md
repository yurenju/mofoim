# 引擎有可移動的游標，釘住改成由前往後一段一段進行

ADR 0003 決定引擎第一版沒有游標：倒退鍵只刪最後一個按鍵，手動選字以「編輯區第幾個字」指定位置。那時編輯區顯示的是引擎猜出來的漢字，使用者看不到自己實際按了什麼，發現猜錯時只能一路刪回去重打。容錯會改動使用者按的鍵，所以「看得到、改得到實際按的鍵」比一般輸入法更重要（研究見 `docs/research/ime-correction-ui.md`）。

我們決定改成拼音輸入法的做法：編輯區照實際按的鍵顯示注音，漢字只出現在候選字裡；引擎有一個以按鍵為單位的游標；釘住只能從還沒釘住的按鍵最前面開始，一次釘住一段。這取代 ADR 0003 的第三點結論，其餘（按鍵序列是唯一事實來源、不事先切字）不變。

按鍵序列因此分成三個部分，由前到後是：

1. **釘住的段**：使用者選定的字詞，每次選字產生一段，顯示成漢字。
2. **游標之前、還沒釘住的按鍵**：引擎只對這一部分猜測並提出候選字。
3. **游標之後的按鍵**：原封不動保留，不參與猜測，等游標移過去才算進來。

## Consequences

- 候選字的第一個永遠是整句猜測，其餘是只涵蓋前面幾個音節的較短字詞。選了較短的字詞，它變成釘住的段，剩下的按鍵接著猜；不能再像以前那樣直接改句子中間的某個字，要先把它前面的部分釘住。我們接受這個限制，換來「不需要在漢字與按鍵之間對位置」的簡單模型。
- 游標永遠在還沒釘住的按鍵裡。游標往前移進釘住的段、或在釘住的段的邊界按倒退鍵時，最後一段的釘住會被撤銷，退回注音（倒退鍵的行為參考 fcitx5 的 BackSpaceToUnselect）。撤銷以「一次選字」為單位，不是以字為單位。
- 釘住的段在引擎裡是「一段按鍵加上選定的文字」，不再是猜測用的圖上的限制條件。引擎只對第 2 部分建圖，釘住的段只提供它最後一個詞當作前文。在游標位置打字或刪除仍然只需要算一個按鍵；撤銷釘住、選字時才整段重算，長度受編輯區上限限制。
- 空白鍵接在還沒打完的音節後面是一聲，這個判斷在按下的當下決定，之後移動游標或改動前面的按鍵不會回頭重新判斷。
- 選字狀態（數字鍵代表選第幾個候選字）放在引擎而不是前端，因為數字鍵平常是注音符號，「同一個鍵在不同狀態代表什麼」是所有平台都要一致的行為，也才能用引擎測試涵蓋。前端只負責把方向鍵等按鍵交給引擎，再照狀態快照畫出來。
- 送出一律送整個按鍵序列的結果：釘住的段，加上其餘所有按鍵（包含游標之後的）的整句猜測。引擎仍然不丟棄按鍵。
- 狀態快照不再是「一格一個字」，而是釘住的段、依音節分組的按鍵、游標位置與候選字。音節的分組只用於顯示與「一次移一個音節」，游標之前照引擎目前的猜測分，游標之後沒有猜測可以依據，以聲調鍵為界。
