# Enter 採用第一個候選字，沒有剩下的按鍵才送出

ADR 0004 規定 Enter 一律送出整個按鍵序列的結果，包含游標之後的按鍵。這讓「改句尾的錯字」很難做（issue #2：長句句尾的「的字」被猜成「得自」）：使用者把游標移到錯字前面，看到前半句猜對了，直覺按 Enter，結果游標之後那個猜錯的部分也一起送出去了。

我們決定 Enter 的意思改成**採用第一個候選字（游標之前的整句猜測）；採用後沒有剩下的按鍵，才送出**。游標在最後時，結果和以前完全一樣；游標不在最後時，Enter 只釘住游標之前的部分，不送出。另外，**一次釘住把游標之前的按鍵用完時，游標跳到最後**，讓游標之後的按鍵接著猜。issue #2 因此變成：Ctrl+← 兩次、Enter、↓ 選「的字」、Enter。

這取代 ADR 0004 裡「送出一律送整個按鍵序列的結果」這一點：送出時仍然送整個按鍵序列，但游標不在最後時按 Enter 不會送出。其餘（候選字只看游標之前、釘住只能從最前面開始、游標之後的按鍵不參與猜測）不變。

調查見 `docs/research/pinyin-ime-correction-ui.md` 的「游標不在最後時的 Enter／空白鍵」。

## Considered Options

- **Enter 只送出游標之前的部分，游標之後的按鍵留在編輯區**：一樣能改句尾的錯字，但多出「送出一部分」這個新概念，和「釘住」、「送出」並列；選字狀態裡同一個 Enter 在第一個候選字上是送出、在其他候選字上是釘住；前半句一送出就不能用倒退鍵撤銷。調查的拼音輸入法沒有一家這樣做。
- **維持原樣，只改提示**：其實已經做得到（選字狀態按 1 釘住第一個候選字，再按 End），但使用者很難發現，而且直覺按 Enter 會把錯字送出去。
- **游標不動，候選字改成涵蓋游標之後**（fcitx5 的做法）：違反 ADR 0004「游標之後的按鍵不參與猜測」，所以照 RIME 的做法把游標移到最後。

## Consequences

- Enter 從此是「選第一個候選字」的快捷鍵：滑鼠點第一個候選字、選字狀態按 1、打字狀態按 Enter，釘住的都是同一段。唯一的差別是 Enter 在沒有剩下的按鍵時會接著送出。這和 RIME 空白鍵的行為一致：先釘住目前這一段，釘到輸入的尾端才送出。拼音輸入法把它放在空白鍵；mofoim 的空白鍵是一聲，所以放在 Enter。
- 選字狀態裡的 Enter 同樣是「釘住反白的候選字，釘完沒有剩下的按鍵就送出」，不再特別處理反白在第一個的情況。還有剩下的按鍵時留在選字狀態，反白第一個，和數字鍵一樣。數字鍵與滑鼠點選只釘住、不送出。
- 游標之前沒有還沒釘住的按鍵時（例如游標剛好在釘住的段後面），Enter 沒有東西可以採用，只把游標移到最後。
- 游標跳到最後只發生在「游標之前的按鍵剛好釘完」時。只釘住其中一部分時，游標不動，剩下的接著在游標之前猜。
- 釘住只涵蓋前半句時，語言模型會少掉跨過切點的詞。例如只釘住「手」，後面的「ㄘㄜˋ」就不能再和它組成「手冊」。這是由前往後釘住本來就有的取捨，使用者要的若是那個詞，就不要在詞中間切開。
- Shift+Enter（原樣送出）和 Esc 不受影響。
